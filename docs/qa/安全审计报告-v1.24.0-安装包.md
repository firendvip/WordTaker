# 弦外小猫 v1.24.0 安装包安全审计报告

- 审计对象：`KittyEcho-1.24.0-arm64.dmg`（Mac）、`KittyEcho-1.24.0-x64-setup.exe`（Windows）
- 审计范围：① 提示词/密钥是否可被用户提取；② 是否可薅羊毛/绕过计费白嫖云端 AI
- 前提：`.asar` 解包对普通用户零门槛（`npx asar extract` / 7z 即可），故 app 内所有源码视为"用户可读"
- 日期：2026-07-09

## 结论速览

| 项 | 结论 |
|---|---|
| 能否看到**本地模型**提示词 | **能**，完整明文可复现（CRITICAL，本地推理本质难隐藏） |
| 能否看到**云端润色**提示词 | **不能**，已移出安装包，客户端只发 `{text, mode}`（安全，设计正确） |
| 能否拿到真实 AI 厂商密钥 | **不能**，未发现 DeepSeek/OpenAI/JWT/DB 密钥硬编码 |
| 能否**薅免费额度/白嫖云端 AI** | **能，高危**，脚本可绕开 App 无限刷 2000 字赠送额度 |
| 能否本地篡改额度骗出付费结果 | **不能**，扣费与额度判定在服务端权威，本地改存储拿不到真实输出（安全） |

**一句话**：付费/扣费链路是安全的（服务端权威）；两个真问题——本地提示词明文、匿名赠送额度可被脚本无限刷——后者危害最大，且**根因在后端、客户端堵不住**。

## 一、提示词与密钥（Mac/Win 一致）

### 1.1 CRITICAL — 本地 LLM 系统提示词完整明文
- 位置：`llm_server.py:75-92`（中文润色 SYSTEM_PROMPT）、`llm_server.py:96-104`（英译提示词），Mac/Win 逐字相同。
- 影响：任何人解包即得完整 system prompt + few-shot 示例 + 分隔符 `【待润色文本开始/结束】` + `/no_think` 控制符，可 1:1 复刻本地润色能力，或据此精确构造注入/越狱 payload 绕过隔离规则。
- 说明：本地推理必须把 system prompt 送入本地模型进程，**无法彻底隐藏**。可选缓解：规则片段运行时远端下发/轻度混淆，或在文档中明确将其定性为"设计上不敏感"（云端提示词已在 `database.js:49` 做此声明，本地未做同等处理）。

### 1.2 HIGH — 中转 relay 访问令牌硬编码
- 位置：`src/helpers/relayConfig.js:20,22` — `RELAY_URL` + `RELAY_TOKEN: "64caa0fb…"`（固定 Bearer，Mac/Win 一致）。
- 影响：解包即得，可绕开客户端直接调该腾讯云 SCF 中转函数，盗用配额/产生云函数费用/当免费润色代理滥用/DoS。作者注释已承认"可服务端轮换吊销"，属已知取舍。
- 建议：给 relay 加限流+来源校验（`x-device-id`+频控），或下线该兜底路径（主路径已走计费后端）。

### 1.3 未发现问题
- 真实 AI 厂商 key：`ai_api_key` 由用户输入并经 Electron `safeStorage`（OS keychain）加密存储，非硬编码；`api.deepseek.com` 等仅为设置页占位默认字符串。
- JWT 签名密钥 / DB 连接串 / 私钥：客户端不存在（正确，应仅在服务端）。
- Vite bundle 未内联任何 `VITE_*` / `import.meta.env` 真实密钥。

## 二、薅羊毛 / 计费绕过

### 2.1 CRITICAL — 匿名赠送额度可被脚本无限刷（危害最大）
- 位置：`src/helpers/deviceIdentity.js:58-96` + `src/helpers/backendClient.js:34-45`；端点硬编码 `https://look3.cn/aiapi`（`/quota`、`/polish`）。
- 事实：设备身份 `x-device-id` 由客户端本地计算（mac `IOPlatformUUID`、win `MachineGuid` 的 sha256），以**明文 HTTP 头**发送，**无签名、无 HMAC、无 nonce/timestamp 防重放**（全量 grep 确认）。
- 薅法（无需装 App、无需伪造硬件）：脚本每次带一个随机的假 `x-device-id`（满足 `[A-Za-z0-9._:-]{8,64}` 即可）循环调 `/quota`、`/polish`；若后端把"没见过的 device-id = 新设备 → 送 2000 字"当唯一判据，即可无限白嫖后端 AI。
- 根因：客户端不可信，`x-device-id` 只是"自证身份"，**此洞在客户端无法修复**。
- 修复（后端）：按 IP/ASN 对设备注册限流、同 IP 大量新设备触发风控、赠送领取绑定一次低成本强身份动作（如短信验证码）、对 `/polish`+`/quota` 统一限流。

### 2.2 HIGH — Windows 比 Mac 更易刷
- 位置：`deviceIdentity.js:69-80`。Win 读注册表 `HKLM\...\MachineGuid`（管理员一条命令即可重写→重启得全新身份，可反复）；Mac 读 `IOPlatformUUID`（硬件级只读，需新建虚拟机才能换，成本更高）。
- 修复：同 2.1（服务端兜底）；Win 侧可加主板/磁盘序列号多因子，仅提高成本、不能杜绝。

### 2.3 MEDIUM — 疑似 mock 支付通道需确认生产状态
- 位置：`backendClient.js:154` — `POST /aiapi/payment/mock/pay`。
- 风险：命名暗示测试用伪造"支付成功"。若生产 `look3.cn` 未禁用/未加管理员级鉴权，攻击者可直接调用免费获得付费额度。**需向计费后端核实生产环境是否已禁用/环境隔离。**

### 2.4 LOW — 次要
- `deviceIdentity.js:99-114` 兜底 UUID 存明文 `userData/backend-device-id`，删文件+重启即换新身份（同 2.1 根因）。
- 登录/退出反复领赠送：客户端注释与实现显示后端已堵（登录不重复赠送）；但只要 2.1 成立，攻击者根本不需登录，此闸形同虚设。

### 2.5 正面结论（设计正确、未被薅）
- 额度快照 `_quotaSnap` 仅内存；本地 sqlite 只存 UX 提醒节流值；`cloudRemaining/dailyUsed/dailyCap` 每次从服务端实时读取，从不写回本地作判据。
- 篡改本地 SQLite/store、甚至改 `main.js`/`aiService.js` 让 UI 显示"额度充足"，**也拿不到真实云端 AI 输出**——真正润色在服务端，服务端按自己的余额判定拒绝（`INSUFFICIENT_QUOTA`/`DAILY_CAP_EXCEEDED` 强制拒绝）。扣费权威判定在服务端，这条路径安全。

## 三、附带发现（非安全，打包 bug）

- **Win 包 `backendConfig.js:38` `CLIENT_PLATFORM = "mac"`**（应为 win），导致 Windows 客户端上报 `x-platform: mac`。若后端按平台做风控/能力判断会被污染。建议修正。

## 四、建议动作（优先级排序）

| 优先级 | 动作 | 归属 |
|---|---|---|
| P0 | 后端对 `/quota`+`/polish` 加设备注册限流+IP 风控；赠送领取绑定短信验证 | 计费后端 |
| P0 | 核实生产 `/payment/mock/pay` 是否已禁用/强鉴权 | 计费后端 |
| P1 | relay 加限流/来源校验或下线兜底路径 | 杂项功能 |
| P2 | 修正 Win 端 `CLIENT_PLATFORM` = win | Windows 专项 |
| P3 | 本地提示词定性说明或轻度混淆（可接受现状） | 语音引擎/杂项 |

> 判定：真正需要立即处理的是 P0 两项（都在后端）。客户端侧问题（提示词明文、relay token）属"设计已知取舍"，危害有限。
