# 尾段再唤醒 / 连说 —— QA 测试用例

> 功能：一段录音结束后、胶囊（小猫）消失前的窗口期内，用户可再次唤醒（单击左 Option）立即开始新一段录音并走完整流程（转写→润色→粘贴到光标）；上一段的收尾（转写/润色/粘贴）在后台并行完成、互不干扰。
>
> 实现要点（用例判定依据）：
> - **按段隔离**：每次开录 `segId = ++segCounterRef.current`，同时 `latestSegIdRef.current = segId`；`isLatestSeg()` 判断本段是否仍是「最新段」。
> - **共享 UI 状态（isRecording / isProcessing / isOptimizing）与隐藏胶囊只跟随最新段**：旧段尾段在后台静默收尾，`setIsProcessing/setIsOptimizing` 与 `hideRecorder()` 均以 `isLatestSeg()` 为门控（`useRecording.js` onstop/processAudio、`App.jsx` `handleAIOptimizationComplete` 的 `canHideRecorder`）。
> - **开新段无并发锁**：`toggleRecording` 只要 `!isRecording` 即开新段，不再因「上一段 processing」而拦截；新段开录即 `setIsProcessing(false)/setIsOptimizing(false)`，胶囊回到「录音中」。
> - **段间保序**：转写/润色/粘贴由主进程 FIFO 队列串行，先入先出，天然保证段1在前、段2在后。
> - **双触发去重**：`toggleRecording` 中 `isRecording` 且 `Date.now()-recordingStartRef.current < 800ms` 时忽略；提示音由 `cueStateRef` 同方向去重。
> - **e2e 埋点按段快照**：`onstop` 快照 `segRecEndTs` 随本段下传，`e2e_total_ms = 粘贴完成时刻 - 本段 recEndTs`，两段互不覆盖。
> - **空录音守卫**：0 字节音频静默 no-op；唤醒后 `< MIN_RECORDER_RESIDENCE_MS(800ms)` 的空录音保留胶囊、只丢数据。

## 环境与前置（全局）

- 运行环境：**运行中的 Electron App**（`npm run dev` 或打包版），真实录音→转写→润色→粘贴，非浏览器、非只读代码。
- 唤醒键：单击左 Option；取消键：Esc（录音中生效）。
- 已下载 AI 模型且引擎就绪（`modelStatus.isReady === true`），除非用例另有说明。
- 光标停在可输入的文本框（如备忘录/输入框），用于观察粘贴结果。
- 建议开启日志（主进程 log），便于核对 segId、FIFO、e2e 埋点。

## 优先级说明

- **P0**：核心正确性 / 回归主流程 / 数据正确性，必过。
- **P1**：常见边界与异常。
- **P2**：次要边界、健壮性增强。

## 判定与回归基线

- **保序**：任何连说场景下，屏幕出字顺序必须＝录音结束顺序（段1、段2、段3…）。任一乱序＝P0 失败。
- **不干扰**：新段的任何操作（开录/取消/空录/出错）不得改变旧段的转写/润色/粘贴结果或使其丢失。
- **胶囊归属**：任何时刻胶囊状态与隐藏只由「最新段」驱动；旧段尾段不得隐藏或改写胶囊。
- **主流程零回归**：不使用连说时，逐段行为与改动前逐项一致（胶囊按时消失、不卡态、不重复贴、埋点/入库正常）。
